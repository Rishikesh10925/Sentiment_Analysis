# Synthetic Demo Data

`social_media_sample.csv` is **100% synthetic demo data**, generated by
[`scripts/generate_sample_dataset.py`](../../scripts/generate_sample_dataset.py).
It does not contain any real posts, messages, or accounts from Instagram,
Facebook, YouTube, Reddit, X/Twitter, or WhatsApp.

The `WhatsApp Export` platform value simulates the *shape* of an authorized,
user-exported chat file. It is not derived from, and does not imply access
to, any real WhatsApp conversation.

## Purpose

This dataset exists so the full pipeline (ingestion → preprocessing → ML →
PySpark aggregation → PostgreSQL → API → dashboard) can be built and
demonstrated end-to-end without a real dataset. The pipeline is designed so
this file can later be swapped for a real, authorized/public dataset without
changing any downstream code, as long as the same columns are present.

## Schema

| column   | description                                              |
|----------|-----------------------------------------------------------|
| id       | unique row id                                              |
| platform | Instagram, Facebook, YouTube, Reddit, X/Twitter, WhatsApp Export |
| post_id  | platform-prefixed post identifier (may repeat for injected duplicates) |
| author   | synthetic username                                         |
| text     | raw post text (may include emojis, URLs, mentions, hashtags, messy whitespace, or be empty) |
| date     | timestamp, `YYYY-MM-DD HH:MM:SS`                            |
| topic    | topic label (may be empty)                                 |
| hashtags | space-separated hashtags extracted at generation time (often empty, like real posts) |

## Intentional messiness

To make preprocessing demonstrable, the generator intentionally introduces:

- ~1% rows with missing/empty `text`
- ~3% rows with missing `topic`
- the majority of rows with no `hashtags` (realistic — most posts don't use hashtags)
- ~3% duplicate rows (same content, re-inserted with a new `id`)
- emojis, URLs, `@mentions`, inline hashtags, extra punctuation (`!!!`), and
  irregular whitespace inside `text`

## Regenerating

```bash
python scripts/generate_sample_dataset.py
```

The generator uses a fixed random seed (42), so output is reproducible.

## `social_media_sample_labeled.csv`

The main file above has **no sentiment column** — on purpose, since it
matches the schema a real, un-annotated social media export would have,
and the whole point of the ML stage is to *predict* sentiment, not read
it off a column.

To train and evaluate a supervised sentiment classifier at all, something
has to supply ground-truth labels. Since no real labeled dataset exists
for this project, the generator exposes the sentiment it used internally
to build each post's text as a second, separate file:
`social_media_sample_labeled.csv` (columns: `id, platform, text,
sentiment`, 5,000 rows). This is **not** a real annotated dataset — it is
the synthetic generator's own answer key, used only by `ml/train.py` to
demonstrate training/evaluation. It intentionally excludes the ~150
injected duplicate rows (those exist to test de-duplication, not to train
on) and always has complete text (missing-text rows are a main-file-only
data-quality issue, not something a labeled training set should contain).

In a real deployment, this file would be replaced by an actual labeled
dataset (e.g. a public sentiment corpus or manually annotated sample),
and the main `social_media_sample.csv`-shaped file would remain unlabeled
production data that the trained model predicts on.
